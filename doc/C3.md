# Heat Pump Wi-Fi Controller

## Features

- Supports target temperature
- Supports run mode

## Customize

- Set the temperature step (0.5 by default).

```json
{ "temperature_step": 1 }
```

## Service

### midea_ac_lan.set_attribute

[![Service](https://my.home-assistant.io/badges/developer_call_service.svg)](https://my.home-assistant.io/redirect/developer_call_service/?service=midea_ac_lan.set_attribute)

Set the attribute of appliance. Service data:

| Name      | Description                                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------------------------ |
| device_id | The Appliance code (Device ID) of appliance                                                                        |
| attribute | "disinfect"<br/>"dhw_power"<br/>"fast_dhw"<br/>"zone1_curve"<br/>"zone2_curve"<br/>"zone1_power"<br/>"zone2_power" |
| value     | true or false                                                                                                      |

Example

```yaml
service: midea_ac_lan.set_attribute
data:
  device_id: XXXXXXXXXXXX
  attribute: zone1_curve
  value: true
```

## Split heat pump water heater (model 171000AU)

Some Midea split heat pump water heaters sold in Australia report as device type
`C3` but speak a different protocol from the air-to-water hydronic units above.
Known model:

| Appliance          | Model code (from the Midea app / `.json` config) |
| ------------------ | ------------------------------------------------ |
| Midea MHW-V28WD2N7 | `171000AU`                                       |

The model code is matched automatically: when a `C3` device with one of these
model codes is added, the integration decodes its frames with the hot water
layout and the air-to-water entities above are **not** created. If the stock
integration shows your unit as two climate zones with a tank at 98 °C and error
code 7, it is one of these units.

Add the device the normal way (cloud Token/Key, V3 protocol). Everything below is
local; the Midea app keeps working alongside it.

### Notes

- Commands write the unit's whole settings block (that is how the Midea codec
  works), so the integration keeps a copy of the current settings from every
  status frame and changes only the requested value. Changing several settings
  within one poll interval is safe.
- The target temperature range, the electric heater ambient range and the
  restart offset range are read from the unit and enforced on the entities.
- "Disinfect now" and "Auxiliary heater" are momentary in the app; the unit
  reports them back as on while active.
- The `set_attribute` service accepts the `hpwh_*` attribute names from the
  tables above (for example `hpwh_disinfect_cycle`), plus `dhw_power` and
  `dhw_target_temp`.
- Protocol notes: the layout was taken from Midea's own `T_0000_C3_171000AU`
  codec and is documented at the top of `custom_components/midea_ac_lan/hpwh.py`.
  If you have another split heat pump water heater that shows the 98 °C / error 7
  symptoms, open an issue with its model code and it can be added to the list.
